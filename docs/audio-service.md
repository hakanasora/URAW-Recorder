# 真实音频服务第一阶段

## 链条、线程与原始性

WASAPI 原始包 / 原生格式 / 设备样本位置 → PCM 解码 → 原始输入峰值 → 按会话创建的 CalibrationProcessor（所选频响 FIR / 未启用时直通）→ 软件增益 → 测量分析 / 有界写盘队列 → float32 WAV / RF64、24 位 FLAC 或 LAME VBR MP3。编码与精度边界详见 [压缩录音](compressed-recording.md)。

捕获线程为 MTA / MMCSS Pro Audio，持有 CoreAudio 对象，及时 ReleaseBuffer，只复制到池化包并投递，不操作 XAML、不写盘。单消费者处理队列按样本顺序执行增益、峰值重置、暂停与写入分支。FFT / 音高分析在单独任务读取最新环形窗；可以跳过旧显示窗口，不能静默丢录音样本。写盘另有单消费者队列，采集处理和写盘队列各最多约 2 秒 / 64 MiB，先到者为限；超限、非有限样本或磁盘错误会停止并报告。音频包不连续按是否正在向文件写入分别处理，见下文 2026-10-26 更新。会话代号隔离过期错误和结果。

不主动启用 AGC、降噪、回声消除、未选择的均衡、归一化、采样率转换或限制器。用户明确选择的麦克风频响校准在软件增益之前处理真实样本。PCM 到 float32 是保存格式转换；32 位整数最低有效位可能受 float32 精度限制，不能称整数位精确归档。软件增益属于入口之后的显式处理。RAW 和独占不能绕过不可关闭的硬件、固件、驱动或端点 always-on APO，也不承诺绝对硬件直通。RAW 接受只表示 Windows 接受该请求。参见 [Windows RAW 定义](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/ne-audioclient-audclnt_streamoptions)。

## 模式与异常

- 启动读取当前默认输入；不因仅有默认设备标记变化而更换有效输入。原生 Core Audio 设备通知经 300 ms 合并后刷新列表，待机中新接入的有效输入优先；录制中保持原输入，移除后先完成本次文件，再在剩余设备中恢复共享监看，绝不接着往同一文件录另一支麦克风。
- 启动、待机及停止后为共享，使用设备 MixFormat；菜单模式只决定正式录制，首次默认独占；此后从独立偏好文件读取用户上次选择，与设备无关。暂停保持当前模式和监看。
- 独占模式优先现有格式，其后当前采样率、48k / 44.1k / 96k / 88.2k / 192k / 176.4k；同声道按原格式、24 PCM（含 24-in-32）、float32、PCM32、PCM16 探测，兼顾 WAVEFORMATEXTENSIBLE。只接受驱动 IsFormatSupported 支持的格式。
- 独占请求约 30 ms 事件缓冲；共享请求约 100 ms 缓冲余量，事件到达节奏仍由音频引擎决定，避免繁忙电脑上仅 30 ms 余量过小。独占 duration / periodicity 相同，遇 BUFFER_SIZE_NOT_ALIGNED 读取对齐帧数、重建客户端只重试一次；独占不调用共享专用 GetNextPacketSize。[初始化](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-initialize)、[读取约束](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudiocaptureclient-getnextpacketsize)。
- 只有 RAW_MODE_UNSUPPORTED、缺少 IAudioClient2 / 明确不支持该接口才触发降级选择。设备忙、权限、移除、服务停止不归类为 RAW 不支持。ContentDialog 的允许只对当前设备本次运行的普通共享监看有效；关闭等于停止，换设备清除许可，正式录制依然必须 RAW。独占失败恢复共享并显示错误，不静默改用共享录制。
- 时钟为文件中实际写入的音频帧 / 实际采样率；UI 定时器只取快照。Preparing 等到有效样本写入才进入 Recording。暂停跳过真实样本，不插入静音。停止后排空队列、补齐文件头才成功。
- 写盘异常保留尽力完成的部分文件并报告失败；暂停时提供“丢弃”：有序关闭本次 WAV 后只移除这一份，清零本次时钟，恢复共享监看；非暂停状态不能丢弃。关闭窗口取消首次关闭，异步收尾后再真正关闭。没有用旧数值或模拟数据填补失败。

## 测量定义

**RMS**：300 ms 逐帧滚动，声道样本平方和 / 实际声道数，20log10(sqrt(mean power))，没有 +3 dB。PEAK 为增益后逐样本最大绝对值并历史保持；另留入口峰值及满刻度标志以区分原始削波（整数正满刻度为 1−2^(1−有效位数)，浮点为 ±1）。更换捕获会话保留历史输出 PEAK；重置在队列命令的样本边界执行。无有效输入为破折号；有效全零为负无穷。

**VU**：平均整流进双精度二阶低通，阻尼比约 0.81526、自然频率约 2.16406 Hz，模拟表头而非峰值映射。低频 biquad 如果直接使用单精度系数会产生约 0.26 dB DC 误差，因此表头系数 / 状态使用双精度；FFT 与 Hann 继续复用 NAudio。以 −18 dBFS 峰值正弦的平均整流值 `2/π × 10^(−18/20)` 为 0 VU，原刻度逐段映射指针。按 [VUMT 公开行为](https://klanghelm.com/docs/VUMT_manual.pdf) 核对 300 ms / 99% 和 1%–1.5% 过冲，不宣称认证。

**频谱**：FFT 大小为不小于 Fs×0.170 的 2 的幂（48k 为 8192），Hann coherent gain 补偿。NAudio 前向 FFT 已除 N，普通单边幅度再乘 2，DC 与 Nyquist 不乘 2；各声道幅度平方取平均，再转 dBFS。这里是单频点幅度谱，并非 SPL 或功率谱密度，不能把宽带噪声每个 bin 的数值当整体 RMS。功率域平滑上升 / 回落 20 / 250 ms，dt 来自音频帧差。复用分析窗口，不累积 UI 时钟；后台因调度延迟可以跳过旧分析窗。取最新窗约 60 Hz，音高最短帧差 20 ms；实际产出受输入块及系统调度影响。视觉参考 [Pro-Q 3](https://www.fabfilter.com/help/ffproq3-manual.pdf)，不声称复制其内部系数。倾斜 0 dB/oct。真实频率 kFs/N，经 log Hz / 非均匀 dB 映射；高频像素桶取峰，低频在实际频点间作功率插值，直线连接，无样条虚假过冲；超过 Nyquist 不绘造数据。静态网格 / 表盘缓存。

**音高**：Pitchy v4.1.0 McLeod NSDF，FFT 自相关归一化补偿、抛物线插值，窗口不小于 Fs×0.085 的 2 的幂，范围 27.5–2093 Hz（边界数值容差 0.1 音分）。只在分析分支去 DC；清晰度≥0.9、RMS≥−80 dBFS；三帧中值，失效断开轨迹。较强声道需持续高于当前通道 3 dB 达 200 ms 才换路。音名 / Hz / 音分由同一结果、A4=440 Hz 推导。只用于单音，不保证复调和所有噪声环境。

## 已执行的离线验证（2026-10-25）

- VU 99% 上升 **299.98 ms**、过冲 **1.202%**、衰减到 1% **300.02 ms**；块大小 1 / 127 / 1024 下稳态在 0.1 dB 门限内。
- FFT 整频点、非整频点、双音、白噪声有限值、反相立体声能量平均、DC / Nyquist 单边幅度及静音检查通过。

## 待用户配合：真实硬件与视觉（未执行）

以下不能用编译或离线断言代替。无需安静房间，无需独占整台电脑；用户自己操作，先确认当时不在语音聊天 / 不使用该输入设备。

1. 双击 Start.cmd；查看输入菜单是否显示真实设备、实际格式、共享及 RAW 状态。说话 / 停顿，看读数、VU / 频谱和音高是否响应；明确 RAW 不支持时由用户决定是否允许仅本次普通监看。
2. 先选“共享”，录约 5 秒，暂停 2 秒，继续 3 秒，停止；打开保存目录，在播放器听取，核对文件约 8 秒、没有暂停静音占位。普通监看许可不会使正式录制绕过 RAW。
3. 再选“独占”，短录 5 秒、停止；看实际格式和停止后共享状态。忙 / 禁用独占时应报错并恢复共享，不能假装已独占。
4. 若方便，独占录制中拔下 USB 麦克风，验证报错、失效读数及部分文件；这一项可另约时间。随后刷新设备重连。
5. 用户观察菜单 / 选项卡 / 暂停动画和真实频谱视觉，反馈截图或日志。当前未进行实窗或真实采集验收。

历史首阶段未包含校准及 MP3 / FLAC；现已分别接入，见下方校准说明及 [压缩录音](compressed-recording.md)。重采样、自动跟随系统默认设备、复调音高识别仍未加入。


## 2026-10-25 第一轮用户测试后的更新

用户提供的 WAV、录屏、手机录像和本轮改动 / 待测项见 [第一轮反馈与修复](round2-feedback.md)。新增针对性断言后共 151 项通过，数值检测参数和先前 VU / 音高误差保持不变。偏好文件位于 `%LOCALAPPDATA%/PortableRecorder/preferences.json`，只记忆录制模式，不保存本次 RAW 普通监看许可。

独立绘制周期与音频测量分开：CompositionTarget.Rendering 触发 CanvasControl 重绘，上限 120 Hz / 减少动态效果 60 Hz；XAML 文本和命令状态约 30 Hz，最小化约 4 Hz。表盘与频谱插值只改变视觉过渡，PEAK、RMS、音高检测、VU 二阶状态及写盘不变。指针插值约一个采集包的显示延迟（8–80 ms 范围），频谱像素点 20 ms 无过冲过渡；音高自动滚动使用显示时间，不再等音频包才迈一步。网格、表盘及指针辉光缓存。实际 Draw 回调速率写入 startup 日志，尚未在真实高刷屏确认 120 fps；不把绘制请求数当作显示器实际呈现帧数。


后续更新：绘制目标已从固定 120 Hz 改为后台读取窗体所在屏幕当前刷新率，每秒复查；音分尺也按绘制时间作视觉平滑。现共 171 项后台断言通过。具体实现、系统只读查询结果和实际呈现限制见 round2-feedback.md 的后续记录，测量、写盘和录制时钟未改变。


## 2026-10-26 待机数据不连续恢复

旧实现对待机 / 暂停 / 正式写盘采用同一个 fatal 分支，驱动只要报告一次 DATA_DISCONTINUITY 或有效帧位置跳变，监看就永久停止。现改为：待机和暂停时保留采集客户端、设备、RAW / 独占状态和历史 PEAK，重建全部分析窗并处理当前真实包；不用虚构静音或旧 FFT / 音高连接缺口，新的分析 Segment 使 UI 清除轨迹和插值。正式写入时不改变严格性：停止该文件、排空已接受样本、尽力完成头，标为可能不完整，再恢复共享监看，绝不自动继续同一录音。

共享缓冲请求由 30 ms 提至 100 ms；独占 30 ms 与对齐重试逻辑不变。新增包原生 flags、设备帧位置差、QPC、包长、格式、会话与是否写盘的诊断；区分数据不连续和物理设备断开。191 项离线断言通过。尚未在用户内置麦克风上运行修复版确认，具体证据与复测步骤见 capture-discontinuity.md。
