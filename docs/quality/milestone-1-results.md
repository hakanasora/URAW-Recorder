## 结构整理的范围与取舍

- 将原顶层测试文件拆为测量、采集生命周期、连续性、显示、偏好等组，公共假设备／写盘器独立成测试夹具；执行器可选择组并报告各组结果，不因前一组失败跳过所有后续组。
- WAV、FLAC、MP3 共用同一个带 `RecordingEncoding` 的写盘注入点，测试不再只有 WAV 可以注入失败。没有增加 DI 容器、服务定位器或工厂包装链。
- `UiPresentation` 把录制栏、输入格式、RAW 请求的状态判断从原生控件中分离，`DialogQueue` 管理真实的弹窗互斥职责；MainWindow 保留控件和原生动画，并非仅换成多个 partial 文件。
- 删除没有消费者的 `IAudioAnalyzer`、`ICalibrationStage`，保留确实用于替换采集／写盘的接口。分析器与按会话创建的校准处理器职责不合并。
- 删除没有生产入口的堆叠 VU 布局、未读取 NumericFont、导入后自动选择分支。保留“导入只管理，不自动应用”。
- 两种 writer 的排队／池化有少量相似代码，但收尾与失败策略不同；本轮不强行建立模板基类或通用录音框架。DSP 算法、FFT、卷积及编码器不重写。
- 原子文件工具从校准领域类中独立出来；四种配置保持原文件、原 JSON 字段及对应验证，派生 Encoding 不再冗余序列化。不是配置存储格式迁移。
- 未执行全仓格式化。重点展开有状态转换和多资源错误处理的代码，避免把无关排版混入修复。长期日志轮转、只读数值数组 API 封装仍是低优先级后续项，没有声称它们已引起用户可见问题。
