# 存储与编码依赖质量整改

本轮没有改变偏好文件名和 JSON 字段，没有加入配置框架或仓储层。使用一个小型 `AtomicFile` 工具统一有界读取、同目录临时写入、刷盘及原子替换；每个领域保留自己的格式验证、默认值和中文提示。

## 校准库

- V1 旧索引没有独立启用状态，继续迁移为已绑定即启用。
- V2 必须包含 `Activation`；字段缺失或为 null 属于损坏，提示并停用，不再从“记住的文件”推测启用状态。文件 ID 不区分大小写的重复项目也拒绝，避免 Windows 同一路径产生别名。
- 源文件、当前缓存和孤立同 hash 缓存统一限制为 2 MiB；索引读写限制 8 MiB。
- 写盘成功后才发布内存状态；失败保留旧版本。`CalibrationLibrarySnapshot` 是只读版本视图，包含 Revision、Entries、Warning、选择及路径投影；UI 读取不等待磁盘锁。捕获旧快照后的路径投影仍使用同一快照，避免并发移除导致元数据投影异常。

## 偏好

- 输入格式读写上限 1 MiB；录制模式和编码偏好读写上限 64 KiB。
- 有界文本读取保留原 `File.ReadAllText` 的 BOM 检测兼容性。写入仍是现有 UTF-8 JSON schema。
- `Load(path)` 保留兼容；新 `Load(out warning, path)` 让界面报告损坏/超限及实际默认值。首次缺文件不是错误，不提示。
- 编码配置不再重复序列化派生 `Encoding` 属性；已有含该字段的文件仍可读取。保存无效 enum/品质值会拒绝，不写入无法重新加载的配置。
- 临时文件清理异常不会覆盖首次写入/改名异常；若同时发生，原异常的 `Data` 记录清理失败信息。只清理本次拥有的唯一临时文件。

## FFmpeg 准备

- 固定版本和 hash 保持不变；已有正确缓存不发网络请求。
- 下载进入唯一 `.download` 临时文件，每次请求超时 60 秒、最多 3 次尝试。完整下载且 SHA-256 匹配后才原子发布缓存。
- 旧半包缓存可从同一固定地址恢复；网络或 hash 验证最终失败保留原始原因，不把未验证响应作为可用缓存。每次失败清理自己的临时文件。
- 已解压缓存或安装二进制也验证固定 SHA-256；安装先复制到唯一临时文件，验证后再原子替换。已验证、正在使用的相同二进制不覆盖。
- 上游 dated daily release 的长期保留问题没有通过“latest 回退”掩盖。仍需要项目所有者选定持久依赖存储；本轮没有上传镜像，也没有宣称干净机器能永久从过期上游地址恢复。
- 当前仅本地开发发布；外部发行完整对应源码/构建依赖包的门槛仍见 `third_party/ffmpeg/README.md`。

## 后台验证

`StorageReliabilityChecks` 新增 28 项存储检查：V1/V2 迁移、孤立超大缓存、只读快照与写锁隔离、提交失败不发布、清理警告、BOM 兼容、损坏/超大偏好、旧编码 JSON、原子替换及临时文件清理。独立 artifact 探针已通过。

`tests/EncoderDownloadChecks.ps1` 通过 AST 只加载生产下载函数，以小文件和 mock 网络测试 10 项失败恢复行为；不会访问远程、下载大包、调用麦克风或操作桌面。命令：`& ./tests/EncoderDownloadChecks.ps1`。实际准备脚本已用现有已验证缓存执行通过。
