## 优先整改项

### Q01 · P1 · 重复“继续”会重复保存样本（已复现）

位置：`src/PortableRecorder.Audio/ProcessingPipeline.cs:152`、`AudioEngine.cs:226`。

`PauseAsync(false)` 无条件增加开放区间，重复调用会产生重叠；Deliver 对每个区间分别写盘。本次探针先录 480 帧、暂停、连续继续两次、再录 480 帧，文件实际 1440 帧。不能依赖 UI 按钮禁用代替服务的状态约束。

整改：相同状态命令幂等；明确停止、准备、录制、暂停、收尾期间哪些命令合法。保护正常校准尾部和源帧区间，不改变暂停文件规则。

验收：正常交替、重复暂停、重复继续、并发排队继续、停止后再继续；WAV/FLAC/MP3 的样本数与有效源区间一致，且不产生无界区间。

### Q02 · P1 · 缺失 V2 字段会重新启用被禁用的校准（已复现）

位置：`src/PortableRecorder.Audio/CalibrationLibrary.cs:25`。

V1 与 V2 都在 Activation 缺失/null 时从设备绑定迁移为启用。V2 的禁用本来保留文件绑定，所以损坏索引会绕过用户禁用选择。探针确认重新加载后 Enabled=true 且 Warning=null。

整改：只对 V1 执行旧数据迁移；V2 的必要字段缺失视为损坏，明确警告、保持停用，不能猜测启用。保留健康 V1 迁移及健康 V2 文件记忆。

验收：V1、V2 正常、V2 缺 Activation、Activation=null、无效字段类型、悬空绑定及损坏 JSON。

### Q03 · P2 · 普通 IO 失败被当成重名而重试 100 次（已复现）

位置：`src/PortableRecorder.Audio/AudioEngine.cs:202`、`FloatWaveWriter.cs:24`。

创建文件成功后写头失败，文件已存在；外层仅凭 IOException+File.Exists 判定重名，生成后缀再试。假写盘器复现了 100 次调用。

整改：只对明确的“目标原本已存在”错误有限重试；写入／权限／磁盘失败直接报告。确认文件所有权与清理规则，不删除别人的文件，失败只尽力保留本次内容。

验收：真实 CreateNew 重名不覆盖；写头失败只调用一次；普通 IO/权限错误无重名循环；摘要与录音成功状态不混淆。

### Q04 · P2 · 错误原因在传播与清理中丢失（静态路径确认）

位置：`ProcessingPipeline.cs:92`、`AudioEngine.cs:214、269、387`、`CompressedAudioWriter.cs:103`。

压缩超限／磁盘错误被通用异常包裹；StopWriter 的具体失败可能在 ReportFault 中被原始笼统错误覆盖。多处 catch 在故障收尾中忽略错误，用户可能看不到降低增益／改用 WAV 或临时文件恢复位置。忽略诊断日志自身错误有合理性，不能把所有 catch 一概移除。

整改：区分首要故障与收尾／诊断故障；用户提示保留可操作原因，日志保留完整异常链；故障任务要受观察，禁止错误反过来阻断资源释放。清理失败不得覆盖先发生的根因。

验收：注入超限、写盘失败、完成文件失败、摘要失败与复合失败，分别断言状态、用户原因、Partial、恢复路径和诊断记录。

### Q05 · P2 · 一个资源释放失败会跳过后续资源（静态路径确认）

位置：`AudioEngine.cs:175`、`AudioEngine.cs:387`；同时审查 `WasapiCapture.cs:117` 的原生释放与完成信号。

capture.DisposeAsync 抛错后 pipeline 不会被释放；后台故障任务还可能以未观察异常退出。原生资源释放步骤也需保证完成信号总能送达。

整改：先转移／清空所有权，再独立清理；所有资源都有执行到的释放路径；保留主异常与次异常。SetGain 的公共入口同时拒绝 NaN/Infinity，保留旧增益，避免污染 DSP。

验收：假 capture 释放抛错、重复 Dispose、打开途中失败、旧会话迟到故障、NaN/Infinity；无有效旧快照、无遗留 worker，命令可结束。

### Q06 · P2 · UI 对话框与关闭生命周期不统一（静态路径确认）

位置：`MainWindow.cs:518、630–639、215–242、682–690`。

Message 不维护统一的弹窗互斥；RAW 提示先记录 decision id，再尝试显示。显示冲突时只记日志，该 id 可能再不提示。系统设置匿名事件没有全部解除；Loaded 中 await 后可能在 Closed 已解除订阅之后再次订阅静态 Rendering。

整改：一个轻量的对话框串行入口；提示实际完成后才确认决策；命名事件成对解除；异步回 UI 时核对 lifetime generation/closing。保留现有原生 ContentDialog 与动画。

验收：用可控任务／对话框适配验证冲突后重试、关闭期间查询完成、关闭后不更新／重新订阅。实际焦点与原生窗体由用户最终观察。

### Q07 · P2 · 校准菜单在定时器中不必要地全量刷新（静态路径确认）

位置：`MainWindow.cs:519–530、642–666`、`Models.cs:50–56`、`CalibrationLibrary.cs:33`。

每约 33 ms 重复投影校准列表、O(n²) 查找、设置选项和 Tooltip；Entries 还与持久化共用锁，后台导入慢时 UI 可等待磁盘锁。应减少无变化时的工作，而不是引入另一个定时器或大型事件总线。

整改：用明确的库版本／dirty 标记驱动列表；实时状态与文件列表分别更新；采用 ID 字典比较；只在展示信息变化时更新说明。公开快照不被 UI 修改。

验收：同一状态重复刷新不修改集合／重建说明；一次导入只投影一次；不变状态无磁盘访问。性能收益记录可重复的分配/执行计数，不预先承诺 FPS。

### Q08 · P2 · 持久化边界与反馈不一致（静态路径确认）

位置：`InputFormatPreferences.cs:34`、`CalibrationLibrary.cs:57、96`、`RecordingPreferences.cs`、`EncodingPreferences.cs`、`MainWindow.cs:554`。

输入格式调用校准类的通用 AtomicWrite，两个 Desktop 偏好又复制临时文件逻辑；小偏好无限读取且恢复默认无可见原因；模式保存失败只记日志。孤立校准副本冲突分支用 ReadAllBytes 绕过正常 2 MiB 上限。

整改：仅提取小型、无状态、限长／原子读写工具，领域类继续管 schema；保留各文件与迁移格式，不建设通用配置框架。派生 Encoding 不再多余序列化；保存失败统一说明“本次有效、未保存”。孤立副本读取同样有界。

验收：超大文件、格式损坏、拒绝写入、清理临时文件失败、超大孤立缓存；根因保留，失败不会更新内存中的已持久化状态。

### Q09 · P2 · 编码依赖下载和测试超时不完整（静态路径确认）

位置：`tools/prepare-encoders.ps1:9`、`tests/PortableRecorder.Audio.Checks/EncodingChecks.cs:16`。

网络中断会在最终缓存名留下半包，之后每次构建都失败直到手工删除；测试先无限等 stdout，再给进程退出加超时，不能覆盖实际卡住的位置。

整改：临时下载→限时／有限重试→摘要验证→原子发布，失败只清理自己创建的临时文件；测试读取／退出共用 deadline，超时只终止本次启动的子进程。不更换编码器或放松哈希。

验收：本地 HTTP/下载适配模拟中断、错误哈希与成功重试；受控子进程保持 stdout 打开时，测试仍在期限内失败并释放资源。

依赖长期存储另列待办：上游 daily 构建可能删除，当前缓存受 Git 忽略。需用户选定稳定项目依赖存储再镜像；不自行上传、不改成 latest。外部分发所需对应源码包仍是单独发布门槛。

## 结构与测试整理

1. **MainWindow 不只按行数切 partial**：926 行混合控件、配置状态投影、对话框、服务指令和动画。先提取可纯后台测试的设置／录制栏展示状态计算；MainWindow 留原生控件与动画。必要时再让真正独立的设置区域成为组件。不会先引入 DI 容器、通用 command bus 或层层转发的接口。
2. **删除证实无消费者的旧分支**：MonitorRenderer.NumericFont 未读取；Stacked/StackedVuTop 的生产入口恒为 false；AddCalibration 的自动选择分支已无生产调用。删除前全仓库核对及编译，保持“添加不自动应用”。
3. **抽象只保留实际边界**：IAudioAnalyzer 当前没有消费者按接口使用；ICalibrationStage 也需按消费者确认后决定删除。采集、写盘故障注入边界保留；写盘工厂统一覆盖三种格式，解决当前仅 WAV 可注入的问题，不叠加多层工厂。
4. **去重以故障语义为前提**：两个写盘器有重复的队列／池化代码，但完成与失败策略并不相同。先用回归锁定行为；只抽取真正相同的缓冲队列部分，不建立模板基类或让通用队列拥有文件生命周期。
5. **测试按命名场景和组运行**：DSP、生命周期、校准库、偏好、编码分组；把 FakeFactory/FailingWriter 从顶层 Program 中分离为测试夹具；报告场景与断言分开、真实个人校准文件检查明确执行/跳过。纯 DSP 测试不应每次都下载完整 FFmpeg。暂不迁移测试框架，不盲追覆盖率百分比。
6. **可读性**：优先展开本轮触碰模块的一行多语句和密集 try/catch，给状态转换、音频块所有权与收尾边界命名。不把全仓格式化与缺陷修复混在一个难审阅的大 diff。
