# 采集稳定性加固与诊断结果

日期：2026-10-29。对应执行单：`capture-stability-plan.md`。

## 结论与限度

用户遇到的停录确实由 WASAPI 不连续标志触发，不是已证实的物理断连。旧日志不足以确定缺失帧数及底层诱因。本轮修复了证据缺项，并加固采集线程调度及原生包释放顺序；**尚未复现并确认间歇故障根因，也不能宣称已经根治**。

没有屏蔽 DATA_DISCONTINUITY，没有插入虚构样本或静默改变录制完整性规则。待机／暂停继续自动恢复分析，正式写盘遇到不连续仍明确结束并标记不完整。

## 实现

- 检查 MMCSS Pro Audio 注册结果，失败尝试 Audio；均失败时使用 AboveNormal 并记录原生错误。不得以 MMCSS 服务运行代替线程注册成功证据。
- 启动前准备等待句柄、连续性状态和常见池化缓冲桶。记录设备实际获准缓冲容量，不把请求时长当实际值。
- 原生音频包只在复制／静音包清零期间持有；先 ReleaseBuffer，再计算连续性、创建托管包并非阻塞投递。异常路径释放原生包及池化数组，投递失败保留明确错误。
- 不连续日志补齐 delta、QPC、模式、采样率、唤醒／读取释放耗时和队列数据。处理线程每十秒汇总健康统计，不在采集线程写日志。
- 队列高水位为处理线程取包时的观测值，并非连续采样得到的绝对最大值。bufferHoldMs 包含 GetBuffer 调用耗时，不能当纯复制耗时。

## 确定性校验

- 新增原生包元数据回归：旧实现因缺少 `delta=240` 日志证据而失败；修复后通过。
- 针对性 continuity/capture/calibration-boundaries：3 组、110 项断言通过。
- 完整音频检查：13 组、665 项断言通过；不是覆盖率百分比。既有不连续停录、待机／暂停恢复、校准边界、编码与资源检查保持通过。
- 发布构建通过，更新 `artifacts/native-preview`。独立代码审查发现的包释放保护及预热桶问题已修正；Git 差异检查通过。
- 未强制制造操作系统 MMCSS 注册失败，未做长时间或高图形负载实窗测试。

证据位于忽略的 `artifacts/capture-stability`：`continuity-red.log`、`targeted-green.log`、`all-checks.log`、`build.log`。

## 授权后台真机对照

用户同意约三分钟内占用 Senary 内置麦克风。未使用 Computer Use、未播放声音、未操作桌面；测试录音仅放项目 artifacts。测试结束后释放采集。测试使用独立配置，不修改系统默认设备或用户保存的设置。

| 测试 | 结果 |
|---|---|
| 旧版直接共享 RAW 采集 30 秒 | 3003 包，未检测到不连续或采集失败 |
| 旧版完整链路，5 秒监看＋约 25 秒共享 WAV | 1,200,960 帧，正常完成，无不连续 |
| 加固版完整链路，同样的短测 | 1,200,000 帧，正常完成，无不连续 |
| 最终代码独占 RAW：约 3 秒录制、2 秒暂停、7 秒继续 | 480,960 帧（约 10.02 秒），正常完成；暂停没有写入两秒占位，停止后恢复共享监看 |

共享实际缓冲为 4800 帧／100 ms，独占为 1440 帧／30 ms；默认设备周期 10 ms。两种模式均成功注册 Pro Audio。共享正常短测最长观测唤醒间隔 27.714 ms、读取释放耗时 0.814 ms；独占为 34.469 ms、0.198 ms。观测队列水位远低于预算，但这不能证明用户故障发生时没有调度延迟或其他竞争。

旧版和新版测试均未复现，因此这些数据不是稳定性改善的统计证明，也不是同一音频输入内容的性能基准。没有主观播放验收或确认实时 UI 负载下的稳定性。

下一次真实故障的日志将能区分原生标志、可信帧位置缺口和时间戳不确定性，并与缓冲、调度及队列状态对照；在取得该证据前不擅自放宽停录规则。
