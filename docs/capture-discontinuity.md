# 内置麦克风待机断读修复

2026-10-26。

## 已确认的证据与限度

用户内置麦克风 Senary Audio，截图与约 15.23 秒录屏显示：待机无读数，手动刷新后恢复。`startup-43604.log` 记录共享 RAW 监看启动约 5 秒后进入 Faulted；刷新恢复约 25 秒后再次进入同一分支。两次消息均来自 ProcessingPipeline 对 `packet.Discontinuity` 的无条件抛错，不是设备移除 HRESULT。

旧日志未保存原生 flags / position delta，不能断言那两次究竟是驱动 DATA_DISCONTINUITY 标志、真实帧缺口、帧位置回跳或系统调度引起。已确认的程序错误是把监看中的一次不连续当成永久故障；不能凭内置设备一直连接就推断采样数据从不会短暂不连续。

Microsoft 对 [DATA_DISCONTINUITY](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/ne-audioclient-_audclnt_bufferflags) 的定义涵盖流状态转换或时序 glitch；[GetBuffer](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudiocaptureclient-getbuffer) 另外定义设备移除 / 资源失效等错误，两者不可混称。

## 行为修改

- **待机监看**：不关闭原生采集客户端，不更换设备或 RAW 状态。每次不连续重建 RMS 窗、VU 检测状态、FFT / 音高窗；沿用历史 PEAK。当前包按真实样本解码，后续包继续分析，不插静音，不把旧音高轨迹接到新片段。新的 Segment 立即清除界面旧轨迹和过渡状态，频谱 / 音高需重新积累真实窗口。
- **暂停**：同上，文件不写入暂停期间的样本，保留本次文件与采集模式；恢复后继续本次文件。
- **正式写盘**：不把“界面恢复”误当录音数据完整。遇到不连续即停本次文件、完成已接受的样本和头部，明确提示文件可能不完整；恢复共享监看供用户观察，但不会自动继续录制。
- **真实错误**：设备移除、权限、3 秒没有包、队列超限、写盘失败仍走各自错误流程，本次未把这些错误一概忽略或当普通监看 glitch。
- **缓冲**：共享模式由请求约 30 ms 改为约 100 ms，增加调度余量；事件周期仍由 Windows 音频引擎决定，不人为攒 100 ms 样本再测量。独占模式约 30 ms 以及等周期 / 对齐重试不变。
- **提示**：输入设备状态 / 顶栏说明短暂不连续恢复次数；不再显示含糊的“断流＝麦克风断开”。
- **诊断**：每次不连续记录 flags、帧位置、与前包的帧差（无法信任时间戳时为 unknown）、包帧数、QPC、采样率、独占 / RAW、会话及写盘状态，不记录音频内容。
- **关闭保护**：同一日志尾部还发现绘制对象已释放异常，增加关闭 / 已释放检查，防止排队回调继续访问已经释放的仪表资源。这不是导致音频状态 Faulted 的分支。

## 针对性后台检查

`dotnet run --project tests/PortableRecorder.Audio.Checks -c Release` 共 **191 项断言通过**。不操作桌面、不打开真实麦克风。

新增：首次启动标志、连续帧、驱动标志而帧位置连续、前向缺口、回跳、时间戳错误及后继锚点、空包；连续 20 次待机不连续后仍保持同一客户端和设备，保持历史 PEAK、重置 RMS / FFT / 音高窗，不插虚构样本；正式录制缺口之前的 WAV 样本数与共享恢复；暂停缺口恢复不改变独占状态、不把暂停样本写入文件。既有解码、频谱 / 音高准确性、VU 响应、RF64、模式和设备测试继续通过。

## 需要用户复测

修复后的实际内置麦克风稳定性尚未实测。本轮未启动窗体或占用麦克风。

打开新版，使用内置麦克风待机监看 1–2 分钟，可正常说话 / 操作其他应用，不要求安静房间。确认不再需要手动刷新才能恢复。若出现不连续提示，读数应自动继续，频谱 / 音高短暂重新积累后恢复。若读数仍永久消失，请提供最新 startup 日志，本次能区分原生标志与具体帧位置异常。正式录制若报数据不连续停止，保留文件并提供日志，不能把这种停止误认为已经证明底层采集完整。
